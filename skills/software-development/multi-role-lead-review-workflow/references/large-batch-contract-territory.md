# 大批量施工：契约先行 + 领地隔离 + 依赖预复制

> 来源：多模块、跨前后端的体验增量批量施工（数十项）实战沉淀。适用于同类批量场景；单点修复或简单配置变更不需要这套。

## 一、开工前：主代理钉死跨路契约

多路并行前，主代理（门禁角色）先把所有路都要依赖的东西**一次性定稿**：

- API 形状（端点/字段/错误码）、共享常量、共享类型定义、迁移脚本。
- **共享文件由主代理预写好全部内容**，然后明令各路「不许改此文件」——否则并行角色互相覆盖（实录：一路加了字段，另一路整个覆写丢掉了前者）。
- 契约写进每路的派工文件，执行角色不需要互相打听。

## 二、按文件域划领地

- 每路一个独立 worktree/分支，只在授权文件列表内改动；**禁止跨领地修改、禁止自行 push/合并**。
- 共享状态文件（如 STATUS/进度文档）只由主代理维护。
- 发现要动的文件属于别的领地 → 只报方案不动手，交主代理裁决。

## 三、依赖预复制，别让每路重装

- 派工前由主代理从主仓**直接复制依赖目录**（含原生模块时优先：预编译产物跨目录复制通常可用），派工里不写「重装依赖」。
- 复制后施工角色先跑一条轻量命令冒烟确认依赖可用；异常才回退完整安装。
- 收益：省去 N 路 × 数分钟的安装等待，也避免安装过程互相抢锁。

## 四、逐波合入 + 全量门禁复跑

- 按波次逐个 merge 主仓；新增型冲突（如翻译文件新增键落在不同位置）通常可自动合并。
- 每波合入后**复跑全量门禁**（后端测试/前端测试/E2E/lint/i18n/构建），不带病进下一波。
- **基线同步**：测试数量等基线文件随本次改动同步更新并随 commit 推送，否则下一批的验收对比会失真。

## 五、合入后的部署验证

- 部署执行迁移回读验证 + 运行环境重建，确认新代码在真实环境生效（不是只在本机绿）。
- 涉及关键路径时，接 `critical-path-smoke-preverify.md` 再交用户终验。
