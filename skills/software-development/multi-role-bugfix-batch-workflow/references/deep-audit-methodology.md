# 深度审计方法论：七方向扫描 + 四类反直觉盲区

> 来源：多次高危区域深度审计（钱链路/状态机/认证）的沉淀。适用于任何项目的安全与稳定性深度审计用例构造与根因分析。

审计高危区域（支付/订单状态机/认证/权限）要两层视角。只读代码找 bug 是浅层审计；本方法要求**先列场景清单再对着代码逐条过**。

## 第一层：七方向扫描

| # | 方向 | 审计时问什么 |
|---|------|-------------|
| 1 | 并发竞争条件 | 两个请求同时到达会怎样？读-改-写之间有没有窗口？ |
| 2 | 边界值与异常输入 | 空值、超长、负数、畸形格式、Unicode/控制字符进来会怎样？ |
| 3 | 状态机完整性 | 每个状态都能进得去出得来吗？有没有死状态？能跳级/回退吗？ |
| 4 | 资源耗尽与溢出 | 计数、金额、分页上限会不会被刷爆？循环有没有终止条件？ |
| 5 | 认证授权绕过 | 直接调内部接口/改 ID/换 cookie 能不能越权？写路径和读路径都查了吗？ |
| 6 | 依赖服务故障 | 第三方超时/挂了/返回脏数据时，本系统是降级还是崩溃？ |
| 7 | 数据完整性 | 中途失败留下什么脏数据？有没有孤儿记录/悬挂引用？ |

## 第二层：四类反直觉盲区（最容易漏的）

1. **并发与时序刺客**：异步乱序、网络抖动导致脏状态；重试风暴；前端连击触发重复提交；消息到达顺序与假设不符。
2. **极端用户行为**：连击、断网重连、乱序操作（后退再前进）、复制粘贴畸形数据、同一账号多设备同时操作。
3. **跨模块隐式耦合**：全局状态污染、缓存/定时器残留、A 模块的重试把 B 模块的锁占死、事件监听没卸载。
4. **业务逻辑悖论**：每个模块单看都正常，链路组合起来出死锁或数据不一致（如"退款比收款多"在单接口校验都过、组合后账不平）。

## 使用方式

1. 审计前先按七方向 × 四盲区**写出场景清单**（每条一句话，形如「连击支付按钮两次」）。
2. 逐条对代码找证据：能防住（给出防线位置）/ 防不住（给出攻击路径）/ 判定不了（需要实测）。
3. 防不住的写成高危用例进修复批；判定不了的进实测批（先取证再修，参见 third-party-report-triage.md 的实测优先批模式）。
4. 审计报告交付格式：场景 | 判定 | 证据（文件:行）| 建议严重度。
